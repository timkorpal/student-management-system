# Student Management System

A full-stack CRUD application for managing student records, built with
**React**, **FastAPI**, and **PostgreSQL**.

The project demonstrates a complete frontend-to-backend workflow,
including REST API development, database persistence, form validation,
error handling, partial updates, and student status management.

## Features

-   Create new student records
-   View all enrolled students
-   Find an individual student by Student ID
-   Update one or more student fields
-   Delete students
-   Mark students as active or inactive
-   Automatically generate five-digit Student IDs such as `00001`
-   Validate email addresses and phone numbers
-   Prevent duplicate email addresses
-   Track record creation and update timestamps
-   Display API validation and not-found errors in the frontend
-   Responsive student listing with visual active/inactive status
    indicators

## Application Architecture

``` text
React Frontend
      |
      | HTTP / JSON
      v
FastAPI REST API
      |
      | SQLAlchemy
      v
PostgreSQL
```

The React frontend handles the user interface and application state. It
communicates with FastAPI through REST endpoints. FastAPI validates
incoming data with Pydantic and uses SQLAlchemy to read and write
student records in PostgreSQL.

## CRUD Operations

  ---------------------------------------------------------------------------------------
  Operation         HTTP Method       Endpoint                          Description
  ----------------- ----------------- --------------------------------- -----------------
  Create            POST              `/students`                       Create a new
                                                                        student

  Read              GET               `/students`                       Retrieve all
                                                                        students

  Read              GET               `/students/{student_id}`          Retrieve one
                                                                        student

  Update            PATCH             `/students/{student_id}`          Update one or
                                                                        more student
                                                                        fields

  Delete            DELETE            `/students/{student_id}`          Delete a student

  Status            PATCH             `/students/{student_id}/status`   Deactivate a
                                                                        student
  ---------------------------------------------------------------------------------------

`PATCH` is used for student updates so the API can update individual
fields without requiring the entire record to be replaced.

## Student Data

Student records include:

-   Internal database ID
-   Five-digit Student ID
-   First name
-   Last name
-   Email
-   Phone number
-   Major
-   Active/inactive status
-   Enrollment date
-   Created timestamp
-   Updated timestamp

The Student ID is generated by the backend after PostgreSQL assigns the
record's primary key:

``` python
new_student.student_id = f"{new_student.id:05d}"
```

This produces IDs such as:

``` text
00001
00002
00003
```

## Validation and Error Handling

The API uses Pydantic models to validate incoming student data.

Examples include:

-   Valid email address
-   Required first and last names
-   Phone number format: `XXX-XXX-XXXX`
-   Required major
-   Enrollment date validation

The application also handles common API errors such as:

-   `404 Not Found` when a Student ID does not exist
-   `409 Conflict` for duplicate unique data such as email addresses
-   `422 Unprocessable Content` for invalid request data

Database transactions are rolled back when necessary to keep the
SQLAlchemy session usable after database errors.

## Student Updates

The update workflow first retrieves a student using their Student ID and
populates the React form with the existing record.

The user can then modify the desired information and submit a `PATCH`
request.

Only editable student fields are accepted by the update schema.
Database-managed values such as the internal ID, Student ID,
`created_at`, and `updated_at` are not directly editable by the client.

The `updated_at` timestamp is maintained automatically when a record
changes.

## Student Status

Students can be marked inactive without deleting their records.

The student list visually distinguishes status:

-   **Active** --- displayed in green
-   **Inactive** --- displayed in red

This allows a student record to remain in the database while
representing whether the student is currently active.

## Getting Started

### Prerequisites

Install the following before running the application:

-   Python 3
-   PostgreSQL
-   Node.js
-   npm

## Backend Setup

From the project directory:

``` bash
cd BackEnd
```

Create and activate a Python environment using your preferred
environment manager, then install the backend dependencies:

``` bash
pip install -r requirements.txt
```

Create a PostgreSQL database and application user.

Example database name:

``` text
students_db
```

Create a `.env` file inside `BackEnd`:

``` env
DATABASE_URL=postgresql+psycopg2://students_user:YOUR_PASSWORD@localhost:5432/students_db
```

Start the FastAPI development server:

``` bash
uvicorn main:app --reload
```

The API will be available at:

``` text
http://127.0.0.1:8000
```

FastAPI's interactive API documentation is available at:

``` text
http://127.0.0.1:8000/docs
```

## Frontend Setup

Open another terminal:

``` bash
cd FrontEnd
npm install
npm run dev
```

The Vite development server will typically run at:

``` text
http://localhost:5173
```

## API Design Highlights

This project intentionally separates responsibilities between the
frontend and backend:

-   React manages UI state and user interaction.
-   FastAPI exposes RESTful endpoints.
-   Pydantic validates API request and response data.
-   SQLAlchemy handles database access.
-   PostgreSQL provides persistent storage.
-   Database-generated and audit fields are controlled by the backend.
-   HTTP status codes communicate success and failure conditions to the
    frontend.
